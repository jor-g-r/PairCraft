# Move to Astro 7 and keep its HTML whitespace as it was
- Status: accepted
- Date: 2026-11-24 · Decided by: the owner (approved the brief; proposal by the agent)

## Context
- measured: `bun audit` reported 16 findings on Astro 6.4.8, one critical (remote code execution when an untrusted AVIF is optimized, fixed in Astro 7.2.8 with sharp 0.35.4) and four high.
- inferred: the site was not reachable through the critical one. `/_image` is public, but there are no remote image sources or uploads.
- measured: after the update `bun audit` reports one high finding, in `path-to-regexp` 6.1.0, which `@vercel/routing-utils` 6.6.1 pins.

## Decision
- `astro` ^7.4.13, `@astrojs/vercel` ^11.0.22, `@astrojs/mdx` ^8.1.6. Node engine >=22.23.4, as Astro requires.
- `compressHTML: true`. Astro 7 defaults to `'jsx'`, which drops the space between inline elements split across lines.
- TypeScript stays on 5.9: `@astrojs/check` accepts 5 or 6 only.
- The lockfile was re-resolved with `--minimum-release-age=259200`, so nothing in it was younger than three days.
- The remaining finding is accepted until the adapter moves. It runs at build time on our own routes, and it is not in the deployed function.

## Alternatives discarded
- Patch sharp alone: the critical finding needs Astro 7.
- `bun update --latest`: it would also move TypeScript to 7.
- Override `path-to-regexp`: it would break an exact pin of the adapter to fix code that never sees user input.

## Consequences
- CSS breakpoints are emitted as `(width>=40rem)`. Tailwind 4 already requires Safari 16.4, which supports it.
- Astro's origin check now looks at `Sec-Fetch-Site` and `Origin`, and skips JSON bodies until Astro 8. A state-changing JSON endpoint must check the origin itself, as `/api/pair` does.
- Enforced by: `compressHTML` in `astro.config.mjs`; prose for the rest. No test covers the origin check of `/api/pair` yet (measured by hand in dev: 403 from another origin).
